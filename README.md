# IVOL Agent — Chrome-расширение

ChatGPT-подобный AI-агент в боковой панели браузера. Видит текущую страницу, заполняет формы, кликает, открывает сайты, ищет в интернете и выполняет JavaScript — с подтверждением каждого опасного действия.

Работает с любым OpenAI-совместимым API (`/v1/responses`, `/v1/models`).

## Установка

```bash
git clone https://github.com/<user>/ivol-agent.git
cd ivol-agent
cp config.example.js config.js
```

Открой [`config.js`](config.example.js:7) и впиши свой `baseUrl` и `apiKey`.

Затем:

1. `chrome://extensions` → включить **Режим разработчика**.
2. **Загрузить распакованное расширение** → выбрать эту папку.
3. Клик по иконке → откроется боковая панель.

Ключ можно задать и через страницу настроек (⚙) — значения из `chrome.storage.local` имеют приоритет над `config.js`.

> `config.js` в `.gitignore`. Ключ остаётся только на твоей машине и никогда не попадает в репозиторий.

## Что умеет

| Действие                                  | Подтверждение                          |
| ----------------------------------------- | -------------------------------------- |
| Прочитать страницу (`get_page_context`)   | нет                                    |
| Прочитать выделенный текст                | нет                                    |
| Скролл к элементу                         | нет                                    |
| Поиск в интернете (`web_search`)          | нет                                    |
| Снимок экрана (`take_screenshot`)         | **да**, с объяснением зачем            |
| Заполнить форму                           | **да**, с показом полей и значений     |
| Кликнуть по элементу                      | **да**                                 |
| Открыть URL                               | **да**                                 |
| Выполнить JavaScript                      | **да, всегда**, с показом полного кода |

Для действий уровня «да» можно поставить галку «не спрашивать для этого домена».

## Разрешения по домену

Разрешение выдаётся **на домен и глобально** — оно живёт в `chrome.storage.local.permissions` (ключ `tool:domain`), а не внутри чата. Поставил галку один раз на `example.com` — этот тул больше не спрашивается на этом домене ни в одном чате и ни в одном окне.

Домен нормализуется до регистрируемого: `www.` и порт срезаются, поддомены схлопываются (`mail.google.com` → `google.com`, `a.b.bbc.co.uk` → `bbc.co.uk`). `localhost` и IP остаются как есть.

Сбросить разрешения домена: кнопка `📝` в панели → **Сбросить разрешения**.

## Системные промпты

Два уровня, оба добавляются к базовому промпту:

1. **Глобальный** — страница настроек (⚙), поле «Глобальный системный промпт». Действует на всех сайтах.
2. **Для сайта** — кнопка `📝` прямо в панели. Промпт привязан к домену (`sitePrompts[domain]`), действует во всех чатах этого сайта и всегда уходит в запрос. Когда для домена промпт задан, кнопка подсвечена.

## Комнаты

Каждый чат — отдельная комната с историей. Комната привязывается к вкладке, к окну браузера и к **стартовому домену**: вернулся на тот же сайт — открылся последний чат этого домена. Два окна работают как два независимых агента.

- `☰` — история чатов: поиск, фильтр по домену, удаление. Список сгруппирован по сайтам (заголовок домена + счётчик), текущий сайт всегда сверху; кнопка «этот сайт» показывает только чаты открытого домена
- `＋` — **новая задача**: чистый контекст для текущего сайта, старый чат остаётся в истории домена
- `📝` — промпт и разрешения текущего домена

**Чат запоминает страницу.** Кроме домена комната хранит конкретный URL (`tabUrl`), на котором шёл разговор. Клик по чату в истории не просто переключает контекст, а возвращает браузер на эту страницу: если вкладка с таким адресом уже открыта — она активируется, иначе на адрес уходит текущая вкладка. Служебные страницы (`chrome://`, Web Store) не запоминаются.

**Пустые чаты не копятся.** Новая комната — черновик: она живёт только в памяти панели и попадает в историю и в `chrome.storage.local` только после первого отправленного сообщения. Открытие сайтов, переключение вкладок и перезапуск панели больше не плодят «Новый чат» в списке.

Всё хранится в `chrome.storage.local`, наружу ничего не уходит кроме запросов к твоему API.

## Уровни рассуждений

Внизу панели — селектор модели и уровня рассуждений: `none`, `low`, `medium`, `high`, `xhigh`, `max`.

Какие значения реально поддерживает провайдер — зависит от него. Некоторые прокси молча схлопывают неизвестные значения в `medium`.

## Отдельная модель для поиска

В настройках (⚙) есть поле **Модель для поиска**. Идея: думает одна модель, ищет другая — обе по одному `baseUrl` и ключу.

- **«Как основная»** (по умолчанию) — в запрос добавляется нативный `{ type: "web_search" }`, поиск выполняет сама основная модель. Так работало раньше.
- **Выбрана другая модель** — нативный тул из основного запроса убирается, вместо него основная модель получает функцию `web_search(query)`. Когда она её вызывает, background делает **отдельный запрос** к поисковой модели с нативным `web_search` и возвращает её текстовую выжимку со ссылками как `function_call_output` — см. [`runWebSearch()`](background.js:748).

Поисковая модель не видит диалог и страницу, поэтому агенту в системном промпте велено класть в `query` самодостаточную фразу со всем контекстом. Цена решения — +1 запрос и несколько секунд на каждый поиск.

## Снимок экрана по кнопке

Если модель пишет «не вижу данные на странице» — у каждого её ответа при наведении появляется кнопка **📷**. Клик делает снимок видимой области и отправляет его в чат обычным сообщением с `input_image`. Подтверждение не спрашивается: действие инициировал ты, а не модель.

## Как это работает

```
Side Panel ──► background service worker ──► POST /v1/responses (stream)
                        │
                        ├─ function_call ──► permission gate ──► карточка в панели
                        │                                              │
                        │                                    Разрешить / Отклонить
                        │                                              │
                        └─ chrome.scripting / chrome.tabs / content.js ┘
```

Agent-loop крутится в service worker, максимум 12 шагов за один запрос. Результат каждого tool возвращается как `function_call_output`, включая случай отказа пользователя — модель это видит и предлагает альтернативу.

Парсер стрима в [`streamOnce()`](background.js:247) поддерживает оба формата ответа: Responses API (`response.output_text.delta`) и Chat Completions (`chat.completion.chunk`). Некоторые прокси принимают вход в формате Responses, но стримят в формате Chat Completions.

При `429/500/502/503/504` — авто-ретрай до 3 попыток с бэкоффом.

## Как агент видит страницу

Гибрид, как у браузерных агентов: основной канал — текст и семантика, картинка по требованию.

1. **`get_page_context`** — очищенный текст + карта интерактивных элементов. У каждого элемента `agent_id`, тип, label, placeholder, значение. Это accessibility-семантика, по которой агент кликает и заполняет формы. Работает всегда, стоит дёшево.
2. **`take_screenshot`** — снимок видимой области через `chrome.tabs.captureVisibleTab`, ужимается до 1024px и JPEG q60. Модель вызывает его сама, когда текста не хватает: график, canvas, картинка без alt, вопрос про вёрстку.

Почему не только скриншоты: клик по `agent_id` детерминирован, клик по координатам — нет; длинные строки (промокоды, артикулы) модель с картинки читает с ошибками.

Технический нюанс: `function_call_output` принимает только текст, поэтому картинка уходит **отдельным сообщением** с `input_image` сразу после результата тула — см. [`runAgent()`](background.js:290).

## Ограничения

- Не работает на служебных страницах `chrome://`, `chrome-extension://` и в Web Store.
- Карта элементов ограничена 400 элементами, текст — 12 000 символов.
- Ключ хранится в `chrome.storage.local` в открытом виде. Это инструмент для личного использования, не публичное расширение для Web Store.
- `run_script` выполняет произвольный JS на странице в `world: "MAIN"`. Всегда читай код в карточке подтверждения перед тем, как разрешить.

## Разработка

```bash
# проверка синтаксиса
for f in *.js lib/*.js; do node --check "$f"; done
```

После правок: `chrome://extensions` → **⟳** на карточке → **закрыть и заново открыть боковую панель** (сама не перерисовывается). Версию видно бейджем внизу панели.

Сброс хранилища: F12 на панели → `chrome.storage.local.clear()` (сотрёт комнаты, разрешения и промпты сайтов).

Ключи в `chrome.storage.local`: `rooms`, `currentRoomByWindow`, `deletedRooms`, `settings`, `permissions`, `sitePrompts`, `modelsCache`.

`deletedRooms` — список id удалённых чатов. Панелей может быть несколько (по одной на окно), поэтому запись идёт со слиянием: без этого «могильника» слияние со storage воскрешало бы только что удалённый чат.
